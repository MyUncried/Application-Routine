# PRE-3 — Schéma cible et frontières d’écriture

Baseline applicative exclusive : `1ddfb6d144552f578388257adc78db47ab5992c8`. Proposition technique à soumettre à la revue VNext, puis à l’approbation propriétaire ; aucun schéma livré.

## Représentation canonique

`ExecutionParameters` version 1 : `version`, `mode`, `series`, `sideMode`, `sideOrder`, `sideRecoverySeconds`, `cadenceBeepIntervalSeconds`, `countdownSeconds`, `endSeconds`. Le nom logique du bip suit Bip v2 ; les fixtures d’oracle utilisent un champ local `cadence` qui n’est pas un DTO applicatif. `series` est discriminé par `kind: UNIFORM | VARIABLE` : uniforme porte `count`, `target`, `pauseSeconds` ; variable porte une collection ordonnée de lignes `{target, pauseSeconds}` dont la longueur donne N. L’état variable ne dépend jamais de l’égalité des lignes. `target` dépend du mode : secondes Durée, nombre Répétitions, null À l’échec. Une cible null dans un brouillon Durée/Répétitions est incomplète et non persistable. Pas de champ de cadence par ligne.

N=1 est normalisé avant tout calcul et projection : uniforme, première ligne actuelle, ordre BY_SIDE. Les réserves variables et d’ordre sont exclusivement volatiles dans le sous-brouillon ouvert. À ✓, seule la représentation effective est transférée au parent. R appartient à l’occurrence, jamais aux paramètres ni à la définition Catalogue. Phrase, segments, total et pilote Séries/Total ne sont pas stockés.

Créer `ExecutionParameters.ts`, `ExecutionParametersDraft.ts`, `executionCalculations.ts`, `executionPhrase.ts` et `exerciseSnapshot.ts` dans `src/domain/activities/`. Fonctions pures, sans React, SQLite, Expo, Profil implicite ou clock. La validation partagée des nouveaux paramètres est la seule autorité ; les erreurs identifient le mode, le champ et la Série concernés. Les adaptateurs historiques se situent aux frontières, jamais dans le calcul.

## Migration additive 009 proposée

Revalider le numéro contre main avant implémentation. Garder 001..008 byte pour byte. `activities` conserve ses CHECK de migration004/005/007/008, ses identifiants, clés composites, positions et associations. Aucune reconstruction de table nécessaire pour les nouveaux paramètres :

- `activity_definitions.execution_parameters TEXT NULL` ; `activities.execution_parameters TEXT NULL` ; JSON versionné, validé avant écriture et après parsing à la lecture. Version inconnue/corruption donne une erreur de données explicite, jamais un fallback silencieux vers les scalaires.
- `activities.category_id TEXT NULL REFERENCES categories(id) ON UPDATE RESTRICT ON DELETE RESTRICT`. Anciennes copies sans Catégorie restent identifiables comme telles ; aucun rattachement automatique à la définition Catalogue, qui n’est pas mémorisée dans cette baseline. Une copie créée depuis Catalogue transporte sa Catégorie. La politique existante d’affectation retirée est conservée lors d’édition.
- `media_assets` garde `id`, `uri`, `created_at` et reçoit des métadonnées nullable : type photo/vidéo, MIME, nom, taille, durée en millisecondes, miniature locale. Ancien asset sans métadonnées reste conservé et lisible sous son URI ; aucun fichier déplacé ni supprimé par migration.
- Nouvelle table `session_activity_media` : `id` stable, `activity_id` FK vers `activities` avec cascade de lien seulement, `asset_id` FK restrictive vers `media_assets`, `position >= 0`, `UNIQUE(activity_id,position)`. L’ordre de l’entrée est la source des positions ; aucun champ de position concurrent côté DTO.

Les scalaires existants restent des projections d’écriture de la première cible/Pause effective, N, mode et direction pour respecter les CHECK et la compatibilité des DTO anciens. Ils ne sont jamais relus comme source si le JSON canonique existe. Pour TO_FAILURE, cibles null ; pour DURATION, durée première cible non nulle et répétitions null ; pour REPETITIONS, inverse. La validation Répétitions passe à100 pour les paramètres PRE-3 ; ne pas élargir accidentellement le nombre de Tours. Une valeur ne devient pas un calcul de somme moyen dans la projection.

Absence de JSON : adapter les scalaires en uniforme/BY_SIDE/bip0 ; conserver cibles, N, Pauses et direction. PC de définition est conservé depuis `side_recovery_seconds` ; la copie historique ne possède aucune colonne PC, son absence reste explicite dans l’adaptateur. Pour CR/Fin absents, proposition de compatibilité neutre0, distincte des défauts Profil10/5 des nouveaux Exercices : ni lecture du Profil courant ni insertion rétroactive de phases. Ce choix doit être jugé dans la revue et présenté au propriétaire avec le plan final.

Les anciennes Pauses/PC peuvent atteindre5999 alors que les nouvelles saisies sont limitées à300. Les lire sans clamp et sans migration destructive ; les signaler à l’édition si elles empêchent une nouvelle validation selon les règles PRE-3. Même principe pour les valeurs historiques hors bornes nouvellement prescrites. Aucune durée réalisée ni table historique n’est recalculée.

## Médias : transaction et fichiers

Acquisition système → copie interne préparée → ajout au brouillon → transaction métier Terminer/Continuer. L’URI relative interne et l’identité de l’asset sont stables ; résoudre sous le dossier document de l’app pour résister à un changement du chemin du container iOS. Une URI héritée absolue reste supportée, sans migration physique automatique. Ne pas persister le cache du sélecteur.

Un registre de prêts de brouillon garde les fichiers préparés tant que l’un des brouillons les utilise. Après abandon confirmé, ne nettoyer que les fichiers de cette préparation, après contrôle DB des liens Catalogue/copies et prêts actifs. Après crash, ne pas lancer de purge globale : conserver l’orphelin éventuel plutôt que supprimer une référence non observée. Le plan de future Exécution devra compléter ce contrôle par les références d’instantanés avant toute suppression d’assets. PRE-3 fournit le serializer versionné et ses tests d’immuabilité, pas un faux Repository d’historique.

Terminer Catalogue écrit asset + définition + liens ensemble ; Continuer Séance écrit asset + occurrences + liens ensemble. Les fichiers sont copiés avant transaction SQLite. Une erreur de copie bloque seulement l’item en erreur avec Réessayer ; une erreur DB garde tous les fichiers prêtés au brouillon pour réessai, sans doublon à double tap. Copier/dupliquer ne copie pas les octets physiques ; liens distincts et immuables. Retirer puis Annuler restitue l’ordre et tous les fichiers.

Source système retenue : D-334/D-335. SDK57 vérifié dans les documentations versionnées ImagePicker/FileSystem/Video. Sélecteur : images+videos, multiple=true, édition=false, limite système0, orderedSelection=true sur iOS ; représentation Current et vidéo Passthrough, sans import réseau implicite. Ces options évitent une conversion demandée par KODJO ; la représentation native réellement retournée est contrôlée sur appareil et n’est pas annoncée byte-identique à tout original.

Sur iOS, les vidéos originales exigent l’autorisation photothèque ; demander au point d’import, gérer accès limité, refus et canAskAgain=false vers Réglages, aucune demande caméra/microphone. Android : sélecteur moderne, pas de mode legacy ouvrant des sources supplémentaires ; traiter le résultat en attente après destruction de MainActivity sans double import. Métadonnées null/absentes valides si le fichier et son type sont exploitables ; aucune erreur sur assetId ou nom système null seuls. Stockage insuffisant et contenu incompatible donnent une erreur locale ; aucune limite de taille/durée produit.

Pour la couverture vidéo, ajouter `expo-video` compatible SDK57 uniquement pour génération de miniature avec `createVideoPlayer`/`generateThumbnailsAsync`, sans lecture ni audio ; libérer explicitement l’objet natif. Un adaptateur garde la miniature en mémoire/reconstruit depuis le fichier stable à la réouverture ; ne persister ni SharedRef native ni pseudo-URI. La persistance d’une miniature physique, si retenue, nécessite une API d’export image vérifiée avant fixation du create slot correspondant. `expo-video-thumbnails` est écarté : page57 annonce sa dépréciation et ne garantit pas son support. Aucun moteur d’exécution ou contrôle de lecture vidéo introduit.
