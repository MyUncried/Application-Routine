# PRE-4 BMAD — préparation de la recette sur iPhone

Décision Q5 du 2026-10-16 : Hermann fait la recette visuelle et tactile sur iPhone, à partir d'une version identifiable et d'une liste de scénarios. **Aucune publication EAS n'est autorisée à cette étape.**

Ce document prépare la recette. La liste des scénarios sera dérivée des stories BMad et de leurs critères d'acceptation, une fois celles-ci rédigées et revues. Une suite de tests verte ne remplace jamais cette recette (`AGENTS.md`).

## 1. Identification de la version recettée

Chaque session de recette commence par consigner :

- le commit de `bmad/pre4-comparaison`, hash complet ;
- l'état de l'arbre au moment du lancement : propre, ou liste des fichiers modifiés ;
- le mode d'installation sur l'iPhone et sa version, à choisir avec Hermann avant le développement, hors EAS tant que celui-ci n'est pas autorisé ;
- le modèle d'iPhone, la version d'iOS et le réglage de taille de texte (ED-22 couvre le texte agrandi) ;
- l'état des données de départ, voir le §2.

## 2. Données de départ pour la préservation (ED-18, ED-19, ED-21)

La recette doit vérifier qu'aucune donnée existante n'est perdue. Il faut donc partir d'une installation qui contient des données créées **avant** PRE-4, avec la version de la base `c32e360d` :

- des Exercices en ancien mode À l'échec, en Durée et en Répétitions ;
- des séries identiques et variables, avec pauses et bip ;
- des copies en Séance ;
- des médias ordonnés ;
- des Catégories et des Zones.

La procédure ci-dessous (story 1.4, AC6) prépare ces données sur l'iPhone, puis installe PRE-4 par-dessus sans les effacer. La même préservation est prouvée par les tests sur une base SQLite fichier réelle (`src/infrastructure/database/__tests__/preservation.story14.test.ts`). Ces tests ne remplacent pas la recette.

### 2.4 Étape 4 : rendre illisibles une Définition et une Copie (Q19)

L'interface ne permet pas de produire un Exercice aux paramètres illisibles. On applique donc un **patch temporaire** dans la copie jetable de l'étape 1, jamais dans la branche livrée. Le patch est versionné uniquement comme fichier de procédure : `docs/preparation/PRE-4/bmad/recette-patch-illisibles.diff`. Il ne touche que `src/infrastructure/database/initializeDatabase.ts` de la copie jetable.

À chaque démarrage, tant que la base est en version 9, le patch compte d'abord les lignes visées :

- la Définition nommée « Exercice illisible » ;
- les Copies de la Séance « Séance vidée ».

Il n'écrit que si ces comptes valent exactement 1 et 1. Il donne alors aux deux lignes le texte `{not json` comme paramètres et journalise `[recette PRE-4] Définitions rendues illisibles : 1 ; Copies : 1`. Sinon, il ne modifie rien et journalise `[recette PRE-4] aucune modification : Définitions N ; Copies M`. Il est idempotent : un nouveau démarrage en version 9 réécrit le même texte. Rien d'autre n'est modifié : ni nom, ni Média, ni lien.

Arrêter Metro (Ctrl+C), puis :

```bash
cd C:/Dev/KODJO-BMAD-PRE4/.recette-c32e360d
git apply --check ../docs/preparation/PRE-4/bmad/recette-patch-illisibles.diff
git apply ../docs/preparation/PRE-4/bmad/recette-patch-illisibles.diff
git diff --stat       # consigner : 1 fichier, initializeDatabase.ts
npx expo start
```

**Si `git apply --check` échoue, s'arrêter et le signaler : ne pas appliquer le patch.**

Sur l'iPhone, recharger l'application une fois, puis lire la console de Metro :

- `Définitions rendues illisibles : 1 ; Copies : 1` : poursuivre.
- `aucune modification : Définitions N ; Copies M` : rien n'a été modifié. Corriger dans la version de départ le nom de la Définition ou de la Séance, pour qu'il y ait exactement une Définition « Exercice illisible » et une seule Copie dans « Séance vidée ». Recharger ensuite, jusqu'à lire `1 ; 1`.

Ne pas naviguer ensuite dans la version de départ : elle peut afficher une erreur sur ces deux Exercices, ce qui reste à relever si cela arrive, sans conséquence pour la suite. Fermer l'application, **arrêter Metro**, puis retirer la copie jetable et prévenir Claude :

```bash
cd C:/Dev/KODJO-BMAD-PRE4
git worktree remove --force .recette-c32e360d
git worktree list     # seule la copie principale doit rester
```

Résultat attendu après migration : 2 Exercices écartés, soit la Définition « Exercice illisible » et la Copie de « Séance vidée ». La Copie de « Exercice illisible » dans « R4 Copie modifiée » reste lisible et garde ses Médias P1 et P2. La Définition « R4 Squats » reste lisible.
